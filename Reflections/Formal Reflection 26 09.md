_**“A good workman never blames his tools”**_

### This reflection is about writing the data collection programme I need for my project.
 

When I was writing this programme, I was trying to achieve the creation of something that would successfully search the internet for webpages
and PDF’s relating to my analysis and download them into a clean and readable format. The programme should have been able to strip headers, 
footers and unrelated material from the webpages it downloaded. The programme does run without errors, and it will be able to 
download the required number of webpages for this project. However, it is only half complete after hours of work. 
I had to step away from writing it due to the feelings it invoked in me.

These feelings were mainly related to frustration, because I could not achieve what I wanted the first time. Even after 10 runs of the programme on test websites,
it would not behave as it was required to do. The programme did not strip everything it was supposed to, no matter how many safeguards and filtering techniques I added to it. 
It kept including footers and directories present on the websites. It was supposed to filter these out and not keep them in the downloaded corpus.

To improve the programme, I could have thought more deeply about the processes behind it and consulted more literature before trying to implement it. 
Additionally, I should have tested each line as I went through during the implementation, as I would have caught issues as I went through the code while writing it, 
instead of finding that it did not do what I wanted it to do after writing the whole programme.

During the process, I learnt about Python processes that can strip downloaded webpages more effectively. 
I also learnt that it is important to take frequent breaks, even when you are focusing deeply on something. 
This is because it can help you see problems more clearly and understand what went wrong with more clarity. It can also help with emotional regulation, 
which I should have considered, as my master’s degree will be in psychology.

If I had consulted more literature and taken the time to understand the processes before trying to make it work, 
I would have had more success the first time I tried it. This would mean that it would have taken less work when it was time to do the data collection. 
This is important because this project will take a large amount of time already, and I cannot afford to waste time during the data collection.

To improve my work process in the future, I should remember that I need to breathe and understand that machines respond to what you tell them to do. 
Just because the programme isn’t performing how it should, there isn’t something wrong with my computer or keyboard, and therefore anger at these tools is not justified. 
It is my approach that needs to change. Although the programme runs without error, it currently only downloads webpages, 
and before data collection begins, it needs to be able to download and strip PDF’s as well. 
Therefore, before data collection can begin, significant work still needs to be done on the programme.
